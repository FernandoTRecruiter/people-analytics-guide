Module 1

O que é People Analytics?

People Analytics (PA) é a prática de coletar, organizar e analisar dados sobre pessoas para tomar decisões de RH mais inteligentes, estratégicas e defensáveis com números — em vez de intuição e feeling.

Os 4 níveis de maturidade

01
Descriptive
Responde: "O que aconteceu?"
Relatórios, headcount, tabelas simples. A maioria das empresas brasileiras está aqui.
"Tivemos 18% de turnover no semestre."
02
Diagnostic
Responde: "Por que aconteceu?"
Cruzamento de dados, drill-down, correlações. Dominar este nível já te diferencia.
"O turnover concentrou-se em analistas com menos de 2 anos, na área de Vendas, sob gestores com eNPS abaixo de 20."
03
Predictive
Responde: "O que vai acontecer?"
Modelos estatísticos e de machine learning. Flight risk, previsão de performance.
"23 colaboradores com score de risco de saída acima de 75% nos próximos 90 dias."
04
Prescriptive
Responde: "O que fazer?"
Recomendações automatizadas baseadas nos modelos. O futuro da área — ainda raro no mercado.
"Para os 23 em risco: recomendamos conversa de carreira. ROI esperado: R$ 480k em custo evitado de turnover."
💡 Estratégia de carreira

Dominar o Level 2 — Diagnóstico — já coloca você no top 20% dos profissionais de RH no Brasil. A maioria das empresas ainda está no Level 1. Não precisa ser cientista de dados para gerar valor real com PA.

Automações úteis para o dia a dia

📧 Relatórios automáticos por e-mail
Python (schedule + smtplib) ou Power Automate. Configure uma vez: toda segunda-feira os KPIs de RH chegam na inbox da liderança automaticamente.
🔄 Atualização automática de dashboard
Power BI Service com gateway de dados, ou Python agendado que gera o arquivo Excel atualizado. Os dados se renovam nos horários definidos sem intervenção manual.
🚨 Alertas automáticos de KPI crítico
Power BI Alerts ou Python + webhook do Slack ou Teams. Quando o turnover ultrapassar X% ou o absenteísmo superar o limite, uma notificação chega sem que você precise monitorar.
📥 Formulários → planilha → dashboard
Qualquer formulário (Google Forms, Microsoft Forms, Typeform) pode alimentar automaticamente uma planilha ou banco de dados via Power Automate ou Zapier — que por sua vez atualiza o dashboard.
🗂️ Consolidação automática de planilhas
Python com pandas ou Power Query consegue ler automaticamente todas as abas ou arquivos de uma pasta e consolidar em uma única tabela — eliminando o copy-paste manual de múltiplas fontes.
🔗 Sincronização entre sistemas
Conectar dados de fontes diferentes — ATS, HRIS, pesquisa de clima — via API ou conectores nativos do Power BI/Python. Uma mudança em uma fonte reflete em todos os relatórios automaticamente.

KPI Formulas — nos 4 ambientes

Cada card mostra: qual tabela usar, o que a fórmula calcula e como implementar em cada ferramenta. As fórmulas estão alinhadas com o schema definido acima.

1
Taxa de Rotatividade (Turnover Rate)
Usa: fato_Historico (Tipo_Evento = "Desligamento") + dim_Colaboradores (Status) para calcular headcount médio
Fórmula base
Turnover (%) = (Saídas no período ÷ Headcount médio) × 100
Headcount médio = (ativos no início + ativos no fim) ÷ 2 · Saídas vêm de fato_Historico, não de uma coluna "Data_Saida"
Exemplo: 200 colaboradores no início, 190 no fim (HC médio = 195), 20 saídas → turnover = 20 ÷ 195 × 100 = 10,3%. Para isolar saídas voluntárias, use KPI 9. 
-- Tabelas: dim_Colaboradores (col C = Status, col E = Data_Admissao)
--          fato_Historico  (col A = ID_Colaborador, col B = Tipo_Evento, col C = Data_Evento)
-- Crie células nomeadas: DATA_INICIO e DATA_FIM com as datas do período

-- 1) Headcount no início (admitidos antes do período)
HC_Inicio  =CONT.SES(dim_Colaboradores!E2:E1000,"<"&DATA_INICIO)

-- 2) Saídas no período — vêm de fato_Historico, não de dim_Colaboradores
Saidas  =CONT.SES(fato_Historico!B2:B5000,"Desligamento",
             fato_Historico!C2:C5000,">="&DATA_INICIO,
             fato_Historico!C2:C5000,"<="&DATA_FIM)

-- 3) Entradas no período (admissões novas)
Entradas  =CONT.SES(dim_Colaboradores!E2:E1000,">="&DATA_INICIO,
               dim_Colaboradores!E2:E1000,"<="&DATA_FIM)

-- 4) Headcount no fim e média
HC_Fim    =HC_Inicio + Entradas - Saidas
HC_Medio  =(HC_Inicio + HC_Fim) / 2

-- 5) Turnover Rate
Turnover_Rate  =(Saidas / HC_Medio) * 100
-- ── Medidas de apoio (crie antes da medida principal) ──────────────────

HC Início =
CALCULATE(
    COUNTROWS(dim_Colaboradores),
    dim_Colaboradores[Data_Admissao] < MIN(dim_dCalendario[Date])
)

HC Fim =
CALCULATE(
    COUNTROWS(dim_Colaboradores),
    dim_Colaboradores[Status] IN {"Ativo", "Licença", "Afastamento"}
)

Average HC = DIVIDE([HC Início] + [HC Fim], 2)

-- Saídas: conta eventos de Desligamento em fato_Historico
Exits in Period =
CALCULATE(
    COUNTROWS(fato_Historico),
    fato_Historico[Tipo_Evento] = "Desligamento"
)

-- ── Medida principal ────────────────────────────────────────────────────
Turnover Rate % =
DIVIDE([Saídas no Período], [HC Médio], 0) * 100

-- Semáforo para KPI card:
Status Turnover =
VAR tx = [Turnover Rate %]
RETURN IF(tx > 20, "🔴 Crítico",
       IF(tx > 10, "🟡 Atenção", "🟢 Saudável"))
-- Saídas vêm de fato_Historico, não de uma coluna Data_Saida.
-- Adapte '2024-01-01'/'2024-12-31' para o período desejado.

WITH saidas_periodo AS (
    SELECT c.Departamento, COUNT(*) AS n_saidas
    FROM fato_Historico h
    JOIN dim_Colaboradores c ON h.ID_Colaborador = c.ID_Colaborador
    WHERE h.Tipo_Evento = 'Desligamento'
      AND h.Data_Evento BETWEEN '2024-01-01' AND '2024-12-31'
    GROUP BY c.Departamento
),
headcount_dept AS (
    SELECT Departamento, COUNT(*) AS hc_total
    FROM dim_Colaboradores
    GROUP BY Departamento
)
SELECT
    h.Departamento,
    COALESCE(s.n_saidas, 0)                           AS saidas,
    h.hc_total                                         AS headcount,
    ROUND(COALESCE(s.n_saidas, 0) * 100.0 / h.hc_total, 2) AS turnover_pct
FROM headcount_dept h
LEFT JOIN saidas_periodo s ON h.Departamento = s.Departamento
ORDER BY turnover_pct DESC;
import pandas as pd

# Carrega as duas tabelas do modelo
df_colab = pd.read_excel("dim_Colaboradores.xlsx", parse_dates=["Data_Admissao"])
df_hist  = pd.read_excel("fato_Historico.xlsx",    parse_dates=["Data_Evento"])

# Período de análise
INICIO = pd.Timestamp("2024-01-01")
FIM    = pd.Timestamp("2024-12-31")

# Saídas: eventos de Desligamento em fato_Historico (não Data_Saida)
saidas = df_hist[
    (df_hist["Tipo_Evento"] == "Desligamento") &
    (df_hist["Data_Evento"]  >= INICIO) &
    (df_hist["Data_Evento"]  <= FIM)
]

# Headcount médio
hc_ini = (df_colab["Data_Admissao"] < INICIO).sum()
hc_fim = df_colab["Status"].isin(["Ativo", "Licença", "Afastamento"]).sum()
hc_med = (hc_ini + hc_fim) / 2

turnover = len(saidas) / hc_med * 100
print(f"Turnover Rate: {turnover:.1f}%")

# Por departamento
saidas_dept = saidas.merge(
    df_colab[["ID_Colaborador", "Departamento"]], on="ID_Colaborador"
)
total_dept = df_colab.groupby("Departamento").size()
turnover_dept = (
    saidas_dept.groupby("Departamento").size() / total_dept * 100
).round(1).rename("Turnover %")
print(turnover_dept.sort_values(ascending=False))

Taxa de Retenção (Retention Rate)
Usa: dim_Colaboradores · Colunas: Status, Data_Admissao
Fórmula base
Retenção (%) = ((HC_Final − Novas_Entradas) ÷ HC_Inicial) × 100
Exclui novas contratações para medir apenas quem "ficou" do período anterior
Por que subtrair novas entradas? Quem entrou no meio do período "infla" artificialmente a retenção. A pergunta certa é: "das pessoas que já estavam, quantas ficaram?" 
-- dim_Colaboradores: col C = Status, col E = Data_Admissao
-- Células nomeadas: DATA_INICIO, DATA_FIM

-- HC inicial: admitidos antes do período
HC_Inicio  =CONT.SES(dim_Colaboradores!E2:E1000,"<"&DATA_INICIO)

-- Novas entradas no período
Novas_Entradas  =CONT.SES(dim_Colaboradores!E2:E1000,">="&DATA_INICIO,
                    dim_Colaboradores!E2:E1000,"<="&DATA_FIM)

-- HC final (ativos + licença + afastamento)
HC_Fim  =CONT.SES(dim_Colaboradores!C2:C1000,"Ativo")
        +CONT.SES(dim_Colaboradores!C2:C1000,"Licença")
        +CONT.SES(dim_Colaboradores!C2:C1000,"Afastamento")

-- Taxa de retenção
Retencao  =((HC_Fim - Novas_Entradas) / HC_Inicio) * 100
-- Novas admissões no período (usa filtro de data do slicer)
Novas Entradas =
CALCULATE(
    COUNTROWS(dim_Colaboradores),
    USERELATIONSHIP(dim_Colaboradores[Data_Admissao], dim_dCalendario[Date])
)

-- Taxa de retenção: quem já estava E ficou
Retention Rate % =
VAR hc_ini  = [HC Início]   -- medida do KPI 1
VAR hc_fim  = [HC Fim]      -- medida do KPI 1
VAR novas   = [Novas Entradas]
RETURN
DIVIDE(hc_fim - novas, hc_ini, 0) * 100
3
Índice de Recomendação (eNPS)
Usa: fato_Avaliacoes · Filtre por Tipo_Avaliacao = "Clima_Organizacional" · Coluna: Nota_eNPS (0–10) · Sempre filtre também por Ciclo_Referencia para não misturar períodos
Fórmula base
eNPS = % Promotores (notas 9–10) − % Detratores (notas 0–6)
Neutros (7–8) não entram no cálculo · Escala resultante: −100 a +100
Exemplo: 40% promotores (9–10), 15% detratores (0–6) → eNPS = 40 − 15 = +25. O que importa é a tendência ao longo do tempo, não um número isolado. 
-- fato_Avaliacoes: col L = Nota_eNPS, col M = Tipo_Avaliacao, col N = Ciclo_Referencia
-- Inclua o ciclo no filtro para não misturar semestres diferentes

Promotores  =CONT.SES(L2:L1000,">=9",M2:M1000,"Clima_Organizacional",N2:N1000,"S1 2024")
Detratores  =CONT.SES(L2:L1000,"<=6",M2:M1000,"Clima_Organizacional",N2:N1000,"S1 2024")
Total       =CONT.SES(M2:M1000,"Clima_Organizacional",N2:N1000,"S1 2024")

eNPS        =(Promotores/Total - Detratores/Total) * 100
-- ⚠️ CALCULATE(COUNTROWS(variável_VAR)) não funciona corretamente em DAX.
-- Use COUNTROWS(FILTER(base, ...)) para filtrar dentro de uma variável.

eNPS =
VAR base  = FILTER(fato_Avaliacoes,
                    fato_Avaliacoes[Tipo_Avaliacao] = "Clima_Organizacional")
VAR total = COUNTROWS(base)
VAR prom  = COUNTROWS(FILTER(base, fato_Avaliacoes[Nota_eNPS] >= 9))
VAR det   = COUNTROWS(FILTER(base, fato_Avaliacoes[Nota_eNPS] <= 6))
RETURN DIVIDE(prom - det, total, 0) * 100
-- ⚠️ Filtro Tipo_Avaliacao é obrigatório: sem ele, mistura Clima
--    com Clima_Desligamento_Voluntario e distorce o resultado.

SELECT c.Departamento,
    ROUND((
        SUM(CASE WHEN s.Nota_eNPS >= 9 THEN 1.0 ELSE 0 END) -
        SUM(CASE WHEN s.Nota_eNPS <= 6 THEN 1.0 ELSE 0 END)
    ) / COUNT(*) * 100, 1) AS eNPS
FROM fato_Avaliacoes s
JOIN dim_Colaboradores c ON s.ID_Colaborador = c.ID_Colaborador
WHERE s.Tipo_Avaliacao   = 'Clima_Organizacional'  -- ← filtro obrigatório
  AND s.Ciclo_Referencia = 'S1 2024'
GROUP BY c.Departamento
ORDER BY eNPS DESC;
import pandas as pd

df_aval  = pd.read_excel("fato_Avaliacoes.xlsx")
df_colab = pd.read_excel("dim_Colaboradores.xlsx")[["ID_Colaborador", "Departamento"]]

# ⚠️ Filtros obrigatórios antes de calcular — sem isso, mistura tipos
df_clima = df_aval[
    (df_aval["Tipo_Avaliacao"]   == "Clima_Organizacional") &
    (df_aval["Ciclo_Referencia"] == "S1 2024")
].copy()

notas = df_clima["Nota_eNPS"]
n     = len(notas)

if n == 0:
    print("Sem respostas no ciclo selecionado.")
else:
    prom = (notas >= 9).sum()
    det  = (notas <= 6).sum()
    enps = (prom - det) / n * 100
    print(f"eNPS: {enps:.1f}  (n={n} | Promotores={prom} | Detratores={det})")

# Por departamento
df_dept = df_clima.merge(df_colab, on="ID_Colaborador")

def calc_enps(g):
    n = len(g)
    return ((g["Nota_eNPS"] >= 9).sum() - (g["Nota_eNPS"] <= 6).sum()) / n * 100

print(df_dept.groupby("Departamento").apply(calc_enps).round(1).rename("eNPS"))
4
Taxa de Absenteísmo (Absenteeism Rate)
Usa: fato_Historico · Filtre por Tipo_Evento IN ("Afastamento", "Licença") · Conta colaboradores únicos com ao menos 1 evento
Fórmula base
Absenteísmo (%) = (Colaboradores únicos com ≥1 afastamento ÷ Headcount ativo) × 100
Atenção: conte colaboradores únicos, não eventos. Se alguém teve 3 afastamentos, conta como 1. Afastamentos concentrados em uma área geralmente indicam problema de gestor ou ambiente antes de problema individual. 
-- fato_Historico: col A = ID_Colaborador, col B = Tipo_Evento
-- dim_Colaboradores: col C = Status
--
-- ⚠️ CONT.SES conta eventos — se alguém teve 2 afastamentos, seria contado 2×.
-- Solução: crie uma coluna auxiliar H em dim_Colaboradores para contar
-- quantos afastamentos cada colaborador teve no período:
--
--   H2 = CONT.SES(fato_Historico!A$2:A$5000, A2,
--                 fato_Historico!B$2:B$5000, "Afastamento")
--   (copie para todas as linhas de dim_Colaboradores)

-- Conta colaboradores ÚNICOS com ao menos 1 afastamento:

Tempo para Preencher Vaga (Time to Fill)
Usa: dim_Vagas · Colunas: Data_Abertura, Data_Fechamento · Filtre sempre por Closure_Reason = "Contratação"
Fórmula base
Time to Fill (dias) = Data_Fechamento − Data_Abertura
Média das vagas encerradas por contratação · Exclua canceladas e congeladas
TTF vs TTH: TTF mede quanto tempo o negócio ficou sem a posição preenchida (da abertura ao aceite). TTH mede a eficiência do processo seletivo (da candidatura do contratado ao aceite). São métricas complementares — uma ruim não implica a outra. 
-- dim_Vagas: col D = Data_Abertura, col G = Data_Fechamento, col J = Closure_Reason
-- Coluna auxiliar (col H) — dias por vaga:

H2  =SE(J2="Contratação", G2-D2, "")

-- Média geral (só vagas encerradas por contratação):
TTF_Medio  =MÉDIASES(H2:H1000, J2:J1000, "Contratação")
Time to Fill (dias) =
AVERAGEX(
    FILTER(dim_Vagas, dim_Vagas[Closure_Reason] = "Contratação"),
    dim_Vagas[Data_Fechamento] - dim_Vagas[Data_Abertura]
)
-- julianday() é função do SQLite.
-- SQL Server: DATEDIFF(day, Data_Abertura, Data_Fechamento)
-- PostgreSQL: Data_Fechamento - Data_Abertura (retorna integer diretamente)

SELECT
    Departamento_Vaga,
    ROUND(AVG(julianday(Data_Fechamento) - julianday(Data_Abertura)), 1)
        AS ttf_medio_dias
FROM dim_Vagas
WHERE Closure_Reason = 'Contratação'
GROUP BY Departamento_Vaga
ORDER BY ttf_medio_dias DESC;
df_v = pd.read_excel("dim_Vagas.xlsx", parse_dates=["Data_Abertura", "Data_Fechamento"])
contrat = df_v[df_v["Closure_Reason"] == "Contratação"].copy()
contrat["TTF"] = (contrat["Data_Fechamento"] - contrat["Data_Abertura"]).dt.days
print(contrat.groupby("Departamento_Vaga")["TTF"].mean().round(1))

Qualidade da Contratação (Quality of Hire)
Usa: fato_Avaliacoes (Media_Gestor em escala 0–5, convertida para 0–100) + dim_Colaboradores (Status, Data_Admissao)
Fórmula base (LinkedIn Talent Solutions · SHRM)
QoH = (Performance_Score + Retention_Score) ÷ 2
Performance_Score = Media_Gestor × 20 (converte escala 0–5 → 0–100) · Retention_Score = 100 se ativo após 12 meses, 0 se saiu
Atenção à escala: fato_Avaliacoes usa escala 0–5 (Media_Gestor). Para o QoH ficar em 0–100 e ser comparável ao benchmark de mercado (>75/100), multiplique Media_Gestor por 20 antes de calcular a média. 
-- dim_Colaboradores: col C = Status, col E = Data_Admissao
-- fato_Avaliacoes: Media_Gestor (0-5) → normalize para 0-100 multiplicando por 20
-- Use PROCV para buscar a Media_Gestor de cada colaborador em fato_Avaliacoes

-- Col M: Nota_Performance_100 = PROCV(A2, fato_Avaliacoes!A:O, 14, 0) * 20
--        (ajuste o índice 14 para a coluna correta de Media_Gestor)

-- Col N: Retencao_1ano (0 ou 100)
-- N2 = SE(E(HOJE()-E2>365, C2="Ativo"), 100,

QoH_Individual  =(M2+N2)/2

-- Média para o período (filtrado por ano de admissão):
QoH_Medio  =MÉDIASES(M2:M1000, ANO_ADMISSAO_COL, 2023)
-- Performance: Media_Gestor (0–5) convertida para 0–100 (×20)
-- Filtra apenas avaliações "Avaliacao_180" para não misturar com Clima
Performance Score (0-100) =
AVERAGEX(
    FILTER(fato_Avaliacoes, fato_Avaliacoes[Tipo_Avaliacao] = "Avaliacao_180"),
    fato_Avaliacoes[Media_Gestor] * 20
)

-- Retenção: % dos contratados com >= 12 meses que ainda estão ativos
Retention Score (0-100) =
DIVIDE(
    CALCULATE(
        COUNTROWS(dim_Colaboradores),
        dim_Colaboradores[Status] = "Ativo",
        DATEDIFF(dim_Colaboradores[Data_Admissao], TODAY(), MONTH) >= 12
    ),
    CALCULATE(
        COUNTROWS(dim_Colaboradores),
        DATEDIFF(dim_Colaboradores[Data_Admissao], TODAY(), MONTH) >= 12
    ),
    0
) * 100

-- Quality of Hire: média entre os dois scores
Quality of Hire =
DIVIDE([Performance Score (0-100)] + [Retention Score (0-100)], 2)

STAR Framework for People Analytics
Every analysis should answer: Situation → Trend → Action → Expected Result. Use this model to structure presentations for C-level and managers.
Why is our turnover above the industry average? +

3-layer diagnosis:

  1. Demographic layer — Segment turnover by department, age group, tenure band (0–6m, 7–12m, 1–3y, 3+y) and manager. A 25% turnover can hide one department at 60% and another at 5%.
  2. Time layer — Plot exits month by month. Seasonal peaks (Jan–Feb post-bonus, Jul–Aug) indicate retention by financial incentive, not genuine engagement.
  3. Reason layer — Cross fato_Historico[Reason] with exit date. If "external offer" dominates, it's a compensation problem; if "climate/manager" dominates, it's a leadership problem.

from datetime import date

df = pd.read_excel("workforce.xlsx", parse_dates=["Data_Admissao","Data_Ultima_Promocao"])

df["meses_sem_promocao"] = ((hoje - df["Data_Ultima_Promocao"]) / pd.Timedelta(days=30)).round()
df["enps_baixo"]         = (df["Nota_eNPS"] <= 6).astype(int)

    df["perf_extrema"]      * 20 +

) / 70  # normaliza 0-100

How do I demonstrate the ROI of a training initiative? +

Modelo de ROI de L&D (Kirkpatrick + Phillips):

  1. Level 1 — Reação: Pesquisa pós-treinamento (NPS do programa). Meta: ≥ 70.
  2. Level 2 — Aprendizado: Pré-teste vs. pós-teste. Meta: ganho ≥ 20 pontos percentuais.
  3. Level 3 — Comportamento: Avaliação 90 dias depois pelo gestor. Use fato_Avaliacoes com Tipo_Avaliacao = 'Pos_Treinamento'.
  4. Level 4 — Resultado: Reduções em turnover, aumento em produtividade, queda em erros operacionais — mensuráveis em KPIs já rastreados.
Formula — Training ROI
ROI (%) = ((Benefício Líquido - Custo Total do Programa) / Custo Total do Programa) × 100

Exemplo:
  Custo do programa de liderança: R$ 80.000
  Redução de turnover de gestores (3 saídas evitadas × R$ 40.000 custo médio de substituição):
      Benefício = 3 × R$ 40.000 = R$ 120.000
  ROI = ((120.000 - 80.000) / 80.000) × 100 = 50%

Tip: Replacement cost ranges from 50% (operational roles) to 200% (technical/management) of annual salary. Use the conservative 50% for ROI calculations — the argument is stronger when the "pessimistic" scenario still justifies the investment.

How do I present People Analytics to the CEO without losing the thread? +

The 3-slide rule for People Analytics at C-level:

  1. Slide 1 — Current situation: 3 KPIs maximum with benchmark context. E.g.: "Turnover 18% (benchmark: 12%). Estimated cost: $800K/year."
  2. Slide 2 — Root cause: One chart with the most relevant segmentation. E.g.: "72% of exits occur in the first 12 months and concentrate in 3 managers."
  3. Slide 3 — Action proposal with ROI: "Structured onboarding + coaching for the 3 managers. Cost: $40K. Expected 30% reduction in early turnover = $240K saved."

Avoid: Dashboards with 15 KPIs, percentages without benchmark context, and recommendations without cost/benefit estimates. CEOs decide based on financial impact — always translate.

Executive meeting opener template:
"We have a $[X]/year problem. The primary cause is [Y]. Proposed solution requiring $[Z] with an expected return of [ROI%] in [timeframe]."
How do I calculate the true cost of a bad hire? +

Components of a bad hire cost:

ComponentTypical estimate
Recruitment cost (CPH)R$ 3.000–15.000
Onboarding and initial training1–3 months of salary
Lost productivity (ramp-up)3–6 months of salary
Team impact (morale, rework)20–30% of team output for 1–3 months
New hire (if terminated)50–200% of annual salary
Conservative total1.5× to 3× annual salary
Estimativa rápida
Custo de Contratação Mal Feita =
    CPH
    + (Salário_Mensal × Meses_Treinamento)
    + (Salário_Mensal × Meses_Produtividade_Perdida × 0.5)
    + CPH  -- novo processo seletivo

Exemplo (Analista Sênior, salário R$ 8.000/mês):
    CPH = R$ 6.000
    Treinamento = 8.000 × 2 = R$ 16.000
    Produtividade = 8.000 × 4 × 0.5 = R$ 16.000
    Nova busca = R$ 6.000
    TOTAL = R$ 44.000 (≈ 5,5 salários mensais)

Use this number to justify Quality of Hire investment: a more rigorous process costing $5K more but avoiding a bad hire worth $44K has an ROI of 780%.

Our eNPS dropped 15 points — how do we investigate and act? +

eNPS drop investigation protocol:

  1. Segment before acting: Is the drop widespread or concentrated in a specific area/level/manager? A 15-point company-wide drop can be 40 points in one area and 0 in others.
  2. Cross with quantitative data: Did turnover or absenteeism rise, or performance drop in the same period? Correlations confirm or rule out hypotheses.
  3. Focus groups with (anonymized) detractors: eNPS measures intensity, not reason. Use qualitative interviews with a representative sample (6–8 people) to understand the "why".
  4. 30-day action plan: Communicate to the organization that data was analyzed and a plan exists. Silence after a survey is one of the biggest HR trust destroyers.
DAX — eNPS variation vs. previous period
eNPS Atual =
VAR base  = FILTER(fato_Avaliacoes, fato_Avaliacoes[Tipo_Avaliacao] = "Clima_Organizacional")
VAR total = COUNTROWS(base)
VAR prom  = COUNTROWS(FILTER(base, fato_Avaliacoes[Nota_eNPS] >= 9))

RETURN DIVIDE(prom - det, total, 0) * 100

CALCULATE([eNPS Atual], DATEADD(dim_dCalendario[Date], -6, MONTH))

Variação eNPS = [eNPS Atual] - [eNPS Período Anterior]

import pandas as pd
from datetime import date

# ── 1. EXTRACT ──────────────────────────────────────────────
def extrair_dados(caminho_excel: str) -> dict[str, pd.DataFrame]:
    """Reads all sheets from the HR workbook."""
    return pd.read_excel(
        caminho_excel,
        sheet_name=["Colaboradores", "Historico", "Avaliacoes", "Vagas"],
        parse_dates=True
    )

# ── 2. TRANSFORM ─────────────────────────────────────────
def calcular_kpis(dados: dict) -> pd.DataFrame:
    hoje = pd.Timestamp(date.today())
    col  = dados["Colaboradores"]
    hist = dados["Historico"]
    aval = dados["Avaliacoes"]

    # Headcount atual
    hc_atual = col[col["Status"] == "Ativo"].shape[0]

    # Turnover Rate (período: ano corrente)
    ano_atual = hoje.year
    saidas = hist[
        (hist["Tipo_Evento"] == "Desligamento") &
        (hist["Data_Evento"].dt.year == ano_atual)
    ].shape[0]

    hc_inicio = col[col["Data_Admissao"].dt.year < ano_atual].shape[0]
    hc_medio  = (hc_inicio + hc_atual) / 2
    turnover  = round((saidas / hc_medio * 100), 2) if hc_medio > 0 else 0

    # eNPS
    clima = aval[aval["Tipo_Avaliacao"] == "Clima_Organizacional"]
    total = len(clima)
    prom  = (clima["Nota_eNPS"] >= 9).sum()
    det   = (clima["Nota_eNPS"] <= 6).sum()
    enps  = round(((prom - det) / total * 100), 2) if total > 0 else 0

    return pd.DataFrame([{
        "Data":          hoje.date(),
        "HC_Atual":      hc_atual,
        "Turnover_Pct":  turnover,

SQL — Reference Queries for People Analytics

Consolidated monthly KPI view
CREATE VIEW vw_kpis_people_analytics AS
WITH
  -- Monthly headcount
  hc_mensal AS (
    SELECT
      strftime('%Y-%m', Data_Evento) AS ano_mes,
      COUNT(DISTINCT ID_Colaborador)  AS hc
    FROM fato_Historico
    WHERE Tipo_Evento IN ('Admissao','Ativo')
    GROUP BY 1
  ),
  -- Monthly exits
  saidas_mensais AS (
    SELECT
      strftime('%Y-%m', Data_Evento) AS ano_mes,
      COUNT(*)                        AS saidas,
      SUM(CASE WHEN Motivo = 'Voluntário' THEN 1 ELSE 0 END) AS saidas_voluntarias
    FROM fato_Historico
    WHERE Tipo_Evento = 'Desligamento'
    GROUP BY 1
  ),
  -- Monthly eNPS
  enps_mensal AS (
    SELECT
      strftime('%Y-%m', Data_Avaliacao) AS ano_mes,
      ROUND(
        (SUM(CASE WHEN Nota_eNPS >= 9 THEN 1.0 ELSE 0 END) -
         SUM(CASE WHEN Nota_eNPS <= 6 THEN 1.0 ELSE 0 END))
        / COUNT(*) * 100, 2
      ) AS enps
    FROM fato_Avaliacoes
    WHERE Tipo_Avaliacao = 'Clima_Organizacional'
    GROUP BY 1
  )
SELECT
  h.ano_mes,
  h.hc                                              AS headcount,
  s.saidas,
  ROUND(s.saidas * 100.0 / h.hc, 2)                AS turnover_pct,
  ROUND(s.saidas_voluntarias * 100.0 / h.hc, 2)    AS vol_turnover_pct,
  e.enps
FROM hc_mensal h
LEFT JOIN saidas_mensais s ON h.ano_mes = s.ano_mes
LEFT JOIN enps_mensal    e ON h.ano_mes = e.ano_mes
ORDER BY h.ano_mes;

 -CONT.SES(Dados_Avaliacoes[Tipo_Avaliacao],"Clima_Organizacional",
           Dados_Avaliacoes[Nota_eNPS],"<="&6))
/ CONT.SE(Dados_Avaliacoes[Tipo_Avaliacao],"Clima_Organizacional")
